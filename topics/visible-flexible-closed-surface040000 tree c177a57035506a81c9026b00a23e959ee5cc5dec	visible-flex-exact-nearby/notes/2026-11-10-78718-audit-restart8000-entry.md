## 3. 类型化 CodeType 身份的完整核验

### 3.1 精确域和编码

core 明确只接受 CPython 3.12、optimize 0，并记录实际完整 sys.version、sys.executable、marshal.version 和 dont_inherit=True。在 code_bytes 中，实际 public co_ 字段集合必须恰好等于 19 个数据字段加 co_lines/co_positions，否则直接拒绝。19 字段为全部参数/局部数/栈/flags、co_code、co_consts、names/varnames、filename/name/qualname、firstlineno、linetable、exceptiontable、freevars/cellvars，以及派生 co_lnotab。后两方法是已有位置表的解码接口，未被当作独立数据遗漏。

递归常量严格分型：None、Ellipsis、bool、int、float、complex、str、bytes、tuple、frozenset、CodeType。未知类型直接拒绝。bool 与 int 先按精确 type 分开；整数保留十进制值；float 用大端 64 位 pack 的十六进制，complex 用两个 64 位分量；因此负零与 NaN payload 不被 Python 数值相等或 JSON 非有限数归一化。字符串 JSON 采用 ensure_ascii，bytes 用 hex；tuple 保留位置；frozenset 的每个完整类型树按规范序列化字节排序；nested code 递归使用同一 19 字段。最终 JSON 禁 NaN、固定分隔符和键排序后摘要。

这一“规范”明确指所列的类型化值树，不声称保留对象共享、intern 引用编号或所有解释器内部状态，也不把 code 树相等单独当作完整函数语义等价。实际数学函数的 globals、closures、defaults 和 alias 仍由原选择器另行检查。这与源码给出的值身份范围一致；本审没有扩大为一般 marshal 或任意 Python 对象的规范编码定理。

capture 先对实际 function 做 raw_function，必须与 selector 已捕获的完整五字段 raw 记录相同。canonical 摘要直接由 function.__code__ 计算；不是把编译所得摘要冒充现场值。随后 check_record 同时核：
