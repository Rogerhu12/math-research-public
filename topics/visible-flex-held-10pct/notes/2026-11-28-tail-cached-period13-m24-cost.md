# 真 M24 三段：26色+13单向的缓存核仍未比原全 J 省时

继真 M16 的26seed完整 A 探针改善后，只选择原 D 真接受 M24/N512/f=.5 的
三个已保存段0、86、1151，使用相同状态、系数、角表、RK步和原保护核验成本。
这不是活 E 的新 J，也没有另开完整1152段 native 请求。

完整实际记录见
[`2026-11-28-tail-cached-period13-m24-cost.json`](2026-11-28-tail-cached-period13-m24-cost.json)，
SHA256 `98e9d59721ad0db9588199d4d46411da34192d314c8c2aa807c21181a96b959e`。
新独立脚本 `probe_native_cached_period13_m24.py` 使用此前已构建的独立候选库，
未修改活 E、原生产 C++、manifest 或任何旧探针。

每段先重放原完整 native state/J，binary64字节与该段保存的生产输出完全相同；
然后构造背景轨道/局部因子缓存，应用26个完整着色方向，再应用13个确定性全分量
单向量。cached state 也逐字节相同，应用阶段没有新增 root call/update。
这13向量仅度量调用成本，不是从实际 M24 GMRES 得到的迭代次数。

本次观测缓存路径为原 full J 的 **1.5979854671倍**。实测峰67596KiB；每段 cache
payload为383776字节，仍不包含 whole-batch 所需的其他所有权/表存储。
当前 M24 没有看到成本收益，所以停止这项优化，不安装到主链。三个段的有限观测
也不能当作所有高 M 性能的定理。

浮点路径仍有此前已记录的区别：逐分量 `1e−12` 绝对乘积尺度比较没有全过，
三个段的最大值分别为 `7.3670027661e−8`、`6.0843720202e−12`、
`3.2638901124e−4`。全局绝对乘积尺度误差至多 `2.2110841928e−17`。
完整逐应用差异、最坏项位置与实际/期望值都保留在 JSON 中。不能用后一个较小
数字抹掉前一个严格门的失败，也不能把缓存方向声称为原接口已返回的全 J。

首次命令误把已有 build record 写成不存在的 `summary.json`，在任何 native
调用之前即 `FileNotFoundError`、exit1；独立工程记录保留。改用真实 `build.json`
后在全新目录执行，才得到上述三段返回。此入口错误没有记成数学失败。
