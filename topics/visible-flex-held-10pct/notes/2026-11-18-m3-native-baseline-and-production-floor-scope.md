## 2. 实际通过的 binary64 基线

三个分片各含 $64$ 次 root 调用。C++ double/V8 回调路径与此次 capture 的 **全部 $54$ 个输出、全部 $130176$ 个事件** 逐字节／逐操作数字段一致；每分片为 $18$ 个输出、$43392$ 个事件。事件核对包含 root 初值、每次求值、域判据、SPD 判据、停止、试步和返回。capture 的前 $16$ 个物理输出也与此前保存的原完整 Jacobian 行逐字节相同。

## 3. `.1` 与实际 `.05` 必须分开

这次只读源审查发现一个明确的默认值差异：

- 原失败记录的顶层 `config` 没有 `projectionFloor`。
- 真正旧 worker 的 `checkpoint.parameters.projectionFloor` 为 `.05`；原 `950f-tail-stage-split.mjs` 从实际 tail parameters 传入这个值。
- capture 直接从省略该字段的 `config` 创建 split engine，继承 generic root 的默认 `.1`；因此保存的 capsule、上述 double 比较和本次三个 long-double 样本都明确属于 **`.1`**。

这一事实不推翻已经逐字节核对的三个固定输出，但不能把 capsule 默认值当作全部生产运行的实际门。后续生产入口应显式保留真实 `.05`。本条不把现有 `.1` long-double 结果改名为 `.05` 的实测结果。
