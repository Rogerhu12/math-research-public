# R87 lambda-zero 残差平台：真实最坏格的精度与剖面窄核

本条检查一个具体假设：原 812→892 点网格细化后 RMS 约 $5.5\times10^{-7}$
没有下降，是否由浮点 RHS/插值相消或 profile 断点错位造成。
唯一输入是设计代理已真实返回的完整 RMS 报告
`R87-lambda0-812-892-original-residuals-20261128/residuals.json`
及其中绑定的两个原未接受完整 checkpoint。没有重算全径向 RHS、J、
Newton 或 BVP，也没有修改尚在进行的后继小正 lambda 求解。

## 原始对象和局部演算

两次最坏格的左端同为 `t=0.30083333333333334`，右端分别为
`0.3008854166666667`、`0.30085937500000004`。
直接取这两个真实相邻节点、完整25维 $Y$、全部8个参数，使用原
`collocation_fun`、`create_spline` 和原五点 Lobatto RMS 公式。
每格只评价两个节点、中点与两个 RMS 侧点。

局部结果精确复现此前报告：

| 实际节点数 | 原最坏格 RMS | 同字面输入扩展精度 Hermite + 原 RHS 后 RMS |
| --- | ---: | ---: |
| 812 | `5.431408116124505e-7` | `5.431408114642144e-7` |
| 892 | `5.515271586743774e-7` | `5.515271584024444e-7` |

扩展精度的两端 $Y$ 和节点仍是原 binary64 数据的**精确提升**，没有
改初猜、换场或调整参数。使用平台实际 `longdouble`（63 位有效小数位，
原 float64 为52位）重新进行该同一 Hermite 片的值/导数演算，然后
调用同一个原 RHS。它只是精度诊断，不是另一个被接受求解器。

同字面 $Y$ 的 RHS 结果差最大仅
`2.992397996059992e-17`、`1.5910666881224778e-17`；
完整扩展 Hermite/RHS 后，残差向量差最大分别为
`2.9711406454574615e-16`、`7.003096883726736e-16`。
这些改变比该格的实际残差小约九个数量级，不能解释所观测的平台。
这不是对所有未来状态的浮点误差定理。

## 真正主要分量与剖面位置

两格最大的单分量均为 radial index 1，即首个三重模式。
812 点时径向/切向/高度三个首模式的 RMS 贡献分别约为
`4.26115e-7`、`1.69069e-7`、`2.91252e-7`；892 点时分别为
`4.32655e-7`、`1.71677e-7`、`2.95809e-7`。
主误差不在那些使用 `pscale=1e-9` 的高模式。代码中 `pscale` 运输支持
参数列，RHS 归一除的是实际 gauge `q=.012`；不能把参数尺度误当成
RHS 的除数并据此推断 $10^{-7}$ 噪声。

原 chart 给 $ds/dt=1.4590149573081437$，两格对应的真实物理区间
起于 `s=0.4389203329901999`，都完全位于同一个最后减速 segment：
参考起点 `0.38549707602339184`、长度 `.08`、速度 `-.5 -> 0`。
五个实际查询的 segment 局部坐标都在约 `.0155` 至 `.0164`，
与该原 ramp 的内部转折 `.05` 也相距很远。
最近已登记真实 profile break 的物理距离至少
`0.0014085752405998408`，大于完整格宽的18倍。
原格附近两倍格宽中没有任何 profile break，全部原定义域检查通过。
因此这次窄格数据也不支持断点错位解释。

另只读核过实际 warped BVP：入口 BC 支持列原本已是原
`core.parameter_derivatives -> flow.project -> pscale/q`，
`bc_jac` 直接使用负 `_initial_jac`；它没有 RHS 旧 fallback 的微步差分。
末端支持参数列为零，此时原 lift 与角图已消失。没有据此改 BC 源。
