# 原径向评估异常路径的 Flow 生命周期修复

实际源码中，Flow 的绑定方法形成自循环，旧 Flow 又可持有核心及其角向缓存。原径向包装只在成功的多分块调用后显式回收；短调用和异常退出跳过回收。原自动 GC 仍在，这个结构事实不能单独解释任何一次真实 signal 9。

独立 `exception_safe_radial_batches.py` 保持原调用、切片、赋值顺序和完整状态/参数列，在所有成功或异常路径的 `finally` 中回收不可达对象。它不清空活缓存、不保留异常对象/traceback、不修改定义域守卫或 Newton 判断，自动 GC 设置保持原样。旧绑定源码没有改动。

一次真实小规模核验读取已保存的 M16/879 点完整原输入，仅取七个真实节点。短调用 block8 与分批 block4 两条路径下，原 RHS、全部状态雅可比及全部参数雅可比均逐位一致。随后对明确未接受的扰动场触发原 Frenet 守卫；没有人工 raise。仅在此生命周期探针中关闭自动 GC，旧 Flow/core 的弱引用确实仍存，按同参数重放新 finally 路径后均释放；异常类型和消息完全一致。

核验真 exit0，用时 5.192331323 秒，峰 RSS 159180 KiB；未构造完整 J、未做 BVP 步、未产生新接受场。完整来源、扰动数值、弱引用结果和实际比较记录 SHA 见[小标量记录](2026-11-28-design-exception-safe-flow-lifecycle.json)。这支付的是一个已复现的资源生命周期缺口，后继 M48 仍必须从最新真实 ordinal4 nodal 检查点继续原求解并通过全部原门；真实中断的原因仍未证。
