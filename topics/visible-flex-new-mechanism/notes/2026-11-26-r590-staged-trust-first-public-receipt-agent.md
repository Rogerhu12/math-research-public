## 8. Hermite 读出自身的失真必须单列

原 `R590_TRUST_PHYSICAL` 记录是在端 stage 与完整 RHS 斜率
构成的 `CubicHermiteSpline` 上采样。末次记录给出

| 原日志字段 | 原打印值 |
|---|---:|
| factored 原 ruling 缺陷 | \(8.063834543578245\times10^{16}\) |
| direct-square 原 ruling 缺陷 | \(8.063834543578243\times10^{16}\) |
| 二表达绝对差 | \(27.875\) |
| C² history 缺陷 | \(2.4128337888014208\times10^{17}\) |
| 原 \(\sigma\) history 缺陷 | \(5.447054024089158\times10^{17}\) |
| kinematic 缺陷 | \(7.755062438654938\) |
| matrix 缺陷 | \(5.939087845603524\) |
| 当前正平方采样最大值 | \(3.215928478629984\times10^{16}\) |

这些是公开程序实际打印的量，均未隐去。但**不能把它们提升为可靠的连续
缺陷上界**：同一 `physical_report` 在末节点打印的速度为
\((5.76157770833351,-5.76157770833351)\)，而上一节完整保存状态与
直接原 BC 的末速度约为
\((-4.629586294251507\times10^{-6},
 +4.732699743455646\times10^{-6})\)。

数学上的 Hermite 插值应在端节点与输入值相同。这里源码以已高达
\(10^{18}\)–\(10^{19}\) 的完整 RHS 斜率构造多项式，再浮点求值；
上述原始记录直接证明该读出没有忠实恢复末节点。从静态表达看，
巨大系数及端点抵消是这个失败的原因；本收据没有额外运行插值或模型
来重新估算误差。因而 `physical_report` 内部的末 \(E,r,T,\nu\) 回付、
采样范围、中心 \(t\) 等大数同样仅按“原始打印读出”保存，
不能倒授准确端状态或连续轨道。

完整原打印读出保存在 checkpoint 的
`original_logged_physical_readout`，其与 `complete_state`
故意分开。以后可在新的求解源中用显式原 ruling / 有限加速度的等价
方程求新状态，并从忠实节点重建；本轮不补跑一个旧 scope
来让收据显得更好。

## 9. 准确的继承范围

本次新增实付内容是：同一真实母上、完整 R590 势与 29 条边界下，

这没有推翻 R590 的精确等价式，也没有给出该母不存在准确解的结论。
