# N 次数直接传播：完整第四函数系数的独立积分接口

日期：2026-11-14。本文对应新模块 `scripts/literature_range_n_polynomial_engine.py`。它实现 [R67](../results/R67-complete-fourth-period-cubic-bulk-count-and-bridge-control.md) 的准确次数递推，为 [R68](../results/R68-paired-bulk-effective-bridge-and-joint-fourth-period-IFT.md) 的有效桥函数提供评价接口。当前只运行一个人为有理 ODE toy；没有编译真实第四目标、评价真实几何或 profile，也没有优化候选。

## 1. 直接传系数，不作大 N 相减

固定同一个有序控制词、bulk 状态、真实桥、全局 profile 和锚点。每个标为 `bulk` 的项目，其 `turns` 定义基长度 $\ell$；整个族中该段真实长度为 $N\ell$。其他项目长度固定。这与把旧有限 N 实例加密是不同操作；改变这个分类或基圈数，必须记录新设计身份。

第二、第三历史分别表示为

$$b=b_0+Nb_1,\qquad c=c_0+Nc_1+N^2c_2.$$

新 DAG 解释器在每个节点直接存储三个实系数 $(p_0,p_1,p_2)$。加法逐系数进行，乘法采用

$$[uv]_0=u_0v_0,\quad [uv]_1=u_0v_1+u_1v_0,$$

$$[uv]_2=u_0v_2+u_1v_1+u_2v_0.$$

它没有以 $N=0,\pm1$ 或很大的数值 N 相减来抽系数。负幂只允许用于完全不含历史的几何表达式。沿用原编译器的符号 weighted degree 检查，权重 $\deg b=1,\deg c=2$；请求超过二次的根会显式拒绝，第二历史的输入二次项也必须严格为零。因此这里的三槽表示不是默默舍弃第四目标中可能非零的更高次项。

profile 的复系数仍由原分离表达式在解释器之外处理。N 是实形式参数，所以 profile 共轭按每个次数逐项共轭；不改变原 $q,\bar q$ 的定义或右锚。纯 $-4$ 通道只需要 $q$、第二 B 和第三 U，后续可避免编译无关的共轭混合历史。

## 2. 一个真实段的传播

在桥上，使用固定真实长度 $\ell$ 的 Gauss 节点与原函数矩阵。先评价几何专属的第二 RHS，更新节点上的 $b_0$；再用更新后的全部第二历史评价第三 RHS，更新节点上的 $c_0,c_1$。$b_1,c_2$ 保留真实段首值。最后在这些节点上评价第四密度三个系数。

在 bulk 上，使用标准化 $t\in[0,1]$，且 $ds=N\ell\,dt$。相同的二次多项式程序在每次积分时将次数上移一位：第二 RHS 加入 $b_1$，第三 RHS 的常数/一次项加入 $c_1,c_2$；第四密度的三个系数加入 $P_1,P_2,P_3$。桥的第四密度则加入 $P_0,P_1,P_2$。

所有历史都从调用方传入的真实上一段端值继承；没有因进入另一桥、P 或倒行块而置零。每步返回：

- `state`：段末全部历史的三个 N 系数；
- `period_increment`：所选各 coefficient 根对 $P_0,P_1,P_2,P_3$ 的增量；
- `coefficient_values`：各根的三个系数在本段节点的值；
- `geometry`、`nodes`、`base_weights`、`measure_degree`：供调用方独立记录真实局部评价与测度次数。

这使调用方能够先累计每个根的四个积分系数，再通过同一个 profile 表展开整个 $P_j(\xi)$ 函数。不能先逐项取绝对值或 L2 再套用多项式关系。ruling 的进一步平方积分、全局 gauge 投影及真函数 Gram 仍由相应 driver 明确实施；本模块不把它们设为零。

常态上的状态节点和第四密度至多二次于标准化 t，三个 Gauss 点足以准确积分这些多项式；这里“准确”指精确算术中的规则。实际 Gauss 节点先以 binary64 生成，DAG 和积分用 long double，因此仍存在舍入误差。桥的变系数积分更须使用冻结控制的真实加密验证。

## 3. 几何身份与内存边界

默认几何入口使用独立的 `literature_endpoint_preserving_h_controls.geometry_jets`。普通冻结段调用原 engine；新受控段先重核 canonical 身份和有理正 b 元数据，再按真实公式给出 $h,k$ 前三导数与 omega。段长始终是真实固定长度或 bulk 基长度，不能在计数提取时另拟合 frame。

DAG 中间数组默认以 128 MiB 为上限，沿同一次 Gauss 评价的节点切块。这只改变浮点执行批次，不改变节点、控制、锚点或表达式。若单个节点都无法容纳，会显式失败。返回的历史和所需根数组另占内存，driver 仍须记录其总规模与运行预算；这里不声称该单一上限就是进程总内存上限。

旧的 `literature_range_numeric_engine.py`、完整编译器和 full4 evaluator 均未修改。新模块的默认 CLI 只接受 `--toy-only`。任何真实输入控制词、完整或纯通道编译、profile 积分和桥响应都必须由本公开仓库的 Actions driver 调用，并核 repo 身份及全部输入哈希。

## 4. 已做的人工检查

toy 使用完全人为的

$$b_s=2,\quad c_s=3+5b,\quad O=7+b^2+11c,$$

并从非零的 $b_0,b_1,c_0,c_1,c_2$ 入值开始，交替传播三个固定长度桥和两个 N 缩放 bulk。长度均为小有理数，不调用实际曲线。独立 Fraction 递推采用真实段长多项式 D：

$$b_{\rm out}=b+2D,\quad
c_{\rm out}=c+(3+5b)D+5D^2,$$

$$\Delta P=(7+b^2+11c)D
+\frac{4b+11(3+5b)}2D^2+\frac{59}{3}D^3.$$

检查覆盖全部端历史系数、完整四个周期系数，以及若干形式 N 处的多项式评价。另一个人工根检查几何负幂乘历史平方；历史负幂和三次观察量均被拒绝。整个 toy 未评价真实 frame、基底曲面或 profile。

## 5. 下一实际诊断所要回答的问题

R62 的四组 $k=\pm1$ 理想有序 bulk 在共同 profile 下给 $P_3(0)=0$。真实桥保持在完整传播中，首个有效函数是

$$\mathcal C_{\rm eff}(\beta)
=P_2(0,\beta)-D_pP_3(0)A^{-1}M_{\rm bridge}(0,\beta).$$

新入口可以给出桥的局部和下游贡献共同作用后的 $P_2$，并用同一纯通道表达式评价 bulk 导数 $D_pP_3$。首个有限公开诊断应记录整个纯函数、其受控桥方向变化、二阶修正项及真实函数空间中的数值方向秩，同时保留完整端点条件和数值误差。

目前并未证明这些方向能解 $\mathcal C_{\rm eff}=0$。旧冻结 R52 profile 已在第一标准常态最高 ruling 门失败，若把它用作接口响应探针，必须明确标为已知失败 profile，不能当作重新获准的完整四阶候选。新真正候选还需同一个 profile 共同支付所有使用状态的必要门、完整第四 ruling/period 和更高阶条件。
