## 4. 记忆具体做了什么、没有证明什么

从旧完成日志读到19个实际norm-attainer记录，按当前bank规则归并为7个原网格/branch方向。模型1至8每次在当前中心重建7行；模型8新增2条完整两网支撑方向，模型9至11每次重建9行。最终bank9条、21次插入、0次驱逐；所有保存的是原行标识与unit-ball方向，不是旧数值 \(A,b\)。

三个容易混淆的数分别为：

- **83**：11个模型初始重建支撑行数之和；
- **85**：各模型最终切平面行数之和，等于83加模型8的2条新行；
- **92**：12个实际 LP 所带切平面行数之和，模型8的首轮7行在第二轮9行中再次出现。

这些是重复模型装配的行计数，不能叫83、85或92个不同新方向。真正本轮新增的不同bank方向是2个。

11次记忆重建共复用77个已选择的当前行导数；模型9至11各请求2条额外当前行导数。连同模型8的首次2条新行，完整oracle累计8次新selected-row J调用，耗时0.104387189 s。相同原ID在不同中心的导数仍必须重新绑定，不能搬用旧中心数值。

单独记忆重建事件的耗时合计约0.06167 s，其中包括模型9至11的上述新行导数；它与oracle导数耗时重叠，不能再次相加。实际12次LP报告耗时合计3.263018616 s。

本轮没有无记忆的同中心反事实。十个模型首轮即可返回的事实不能换算成“节省了某确定数量LP”，也不能用8次接受对旧运行5次接受作因果证明。

本轮 selected-J coarse/fine 累计7.628204546 / 20.534712244 s。首次 selected-J 构造在 active clock 开始之前；所以不能把所有这些累计计时与active38.005 s直接相加后判断越预算。

## 6. 下一项改变的最小边界

下一方案优先处理真实阻断分支：在同一失败full primary \(y\) 已完成两网评价后，若学习了新行，则先保存真实 \(y\) 的两网值、完整行ID与来源，回到同一已接受中心 \(x\)，按扩大后的池重新构造原base、J、primary和完整affine-e/f绑定，然后在同一 \(y\) 和同一总位移下尝试一次原SOC。其意义是支付“扩池使旧Jacobian/行序无效”这一真实缺口；不是忽略现有layout guard。

完整合同应同时要求：

1. 新旧中心、\(y\)、坐标映射、物理宽度和原B完全绑定；新池版本/IDs/J另有明确身份。
2. SOC以 \(x\) 的新J配 \(y\) 的真实残差，不混用 \(y\) 的J或旧池行序。
3. 同一次试点至多一次修正，新增LP/行导数/JVP/验值全部使用原12LP、120秒active和40共享值预算。
4. 修正后仍走所有原真实两网门及下降量条件；若再学习新行，返回最后已接受点，不递归修正。
5. failed trial 的原新增行记录不清零。它不满足旧SOC-hold“所有新行均为0”的条件；不能借重绑定获得持径资格。
6. 原模型和新重绑定模型分别记账。现有complete_models按outer模型zip的报告接口须显式区分，不能插入一个新模型后把后续报告错配。

这些要求将另成最小设计。near-active硬行/邻点覆盖只作为后继可比较方案，不同时混入本次新机制，更不修改原验收门。
