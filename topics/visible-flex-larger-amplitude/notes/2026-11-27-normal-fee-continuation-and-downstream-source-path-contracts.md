The normal producer **can continue the original complete domain in its original output directory**. A different controller step ID alone is not a change of its canonical execution binding. Those consumers read the original scientific/input/stream files at their original paths and bind current source copies by the complete pinned SHA and bytes. There is a separate continuation rule for each output family. Geometry binds the **whole normal report record** and its own three source-file records. R723 requires a fresh output directory on every invocation. The moment producer supports reusing complete integral blocks under the same full execution binding. Mesh production requires a fresh output directory. These are actual existing source contracts, not new admission rules.

A further exact interface boundary is recorded in §8: the currently published original mesh binder accepts an optional **002eb R722** closed report, not a **1782 R723** report. The current complete 20 mesh plans omit that optional argument and are therefore not blocked by a missing closed report. A distinct R723-compatible mesh source branch has been separately requested; it is not claimed to exist or to have run in this note.

### 3.2 Why a new step ID is allowed but an automatically new repo path is not

N.`main` constructs `complete-input-and-request.json` from:

- the complete I.`actual.binding` and its canonical identity;
- every original literal and all 1,024 complete circle requests;
- the whole common 32-stage partition;

Consequently, replacing repo A with repo B changes the canonical actual-input identity even when all 137 files in B have the same bytes. N.`immutable_json` compares the complete existing parsed JSON with the newly encoded object and refuses a different immutable request. It does not perform a path-relocation normalization.

The controller's step ID is not a member of the request, geometry identity, execution binding or per-job header. The *new invoking process's* `GITHUB_SHA`, run/attempt and timing appear in the mutable fee report rather than in these canonical request objects. The original scientific run/source identity remains in the actual-input binding and cannot be changed.

The location of a byte-identical N script copy is also not itself a request field. Thus a new controller checkout may invoke the unchanged N source while explicitly passing the **original normal fee's recorded `--repo` path**. N then loads its pinned accurate modules and I records all runtime roles from that original root. This is conditional on the original whole source files remaining present and unchanged; it is not permission to rewrite a recorded path.

The exact original normal source root is to be taken from the real first fee step's `source_worktree`/command and checked against its bound runtime-source paths. No current or future absolute runner path is inferred in this note. It is specifically the **first normal fee's** source root, which need not be the original solver's checkout.
