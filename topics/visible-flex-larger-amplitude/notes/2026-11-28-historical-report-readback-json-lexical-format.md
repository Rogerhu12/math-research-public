## 2. The only transformation

The existing complete formatter `scripts/resume_20261126/reproduce_complete_historical_note_json_lexical_format.mjs` is reused byte for byte. Its complete identity is 3705 bytes, SHA-256 `8b5f50c536cab06322f53cc92e84ebd968490da3545982b9bd66011e6d39f407`, Git blob `38f115aa1ae2cf5696d921c4a7e0aec4280f1c7f`.

The formatter removes only ASCII space, horizontal tab, carriage return and line feed outside JSON strings, then appends one final newline. Escaped quotes and escaped backslashes are tracked while reading strings. It does not regenerate the JSON from parsed values. Consequently number tokens, negative zero, exponent spellings, integer digits, string escapes, object-member order, duplicate-member spellings, array order and every original value remain exactly as written. Complete regenerated bodies were checked for their recorded byte counts and hashes and for lexical idempotence.

No file is deleted. No source file, theorem, runtime binding, active input, ready object, request, queue, workflow, original port or parent91 object is modified. All source and input references, original parameters, finite diagnostics, failed or pending statuses, unknown termination causes, timestamps, paths and qualifications inside the selected files are retained as original tokens. This is an I/O formatting operation, not a new numerical calculation, an audit of the original numerical methods, or a claim that old conditions have since been paid.
