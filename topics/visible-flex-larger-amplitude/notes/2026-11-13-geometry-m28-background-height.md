# 当前 M28 背景高度的来源与新控制选择

2026-11-13，geometry_audit，AI-assisted。**启发式/数值诊断。**

为避免增幅时尺寸持续上涨，只实例化现有 `alternative-neck-provider.py` 中的真实 `NeckPrefix` 和 `NeckTerminalBridge` 公式，使用当前 accepted M28 的完整 `frozen_profile` 与原 physical cut。没有调用其 linear ODE screen、没有新 BVP、没有 tail。正式 exit $0$，耗时 $2.69055557$ 秒，峰 RSS $62800$ KiB。

背景高度为 $1.9291208510740632$，当前实际前缀的高度最大样值为 $1.926153401821087$；两个量并不相同。以下比例只对背景程序成立：

| 部分 | 背景高度增量 | 总背景高度占比 |
| --- | ---: | ---: |
| 初始 Hermite 段 | 0.8256357006 | 42.8% |
| 两个 loop 转弯合计 | 0.5372886012 | 27.9% |
| 第一次下降转弯 | 0.2844386422 | 14.7% |
| 长下降 coast | 0.1680304734 | 8.7% |
| boost | 0.0943768408 | 4.9% |
| 其余过渡、短 coast、terminal bridge | 0.0193505929 | 1.0% |

因此后续压低高度时，主要代价不在末端小 bridge。loop ratio 已经为 $1.1$，继续压缩两段短 coast 所能节省的直接高度也小。

在**不匹配 core、其余物理参数固定**的诊断里，初始加速度 `start_acceleration` 从 $0.45$ 增到 $0.46$，背景高度从 $1.9291208510740632$ 降到 $1.926445563773525$；中心差分导数约为 $-0.2690845007$。该参数已在真实三控制延拓器的外部控制接口中，值得在后续完整实际 Jacobian 中增加一个 core-held 列，再判断它是否能同时节省实际高度和曲率预算。此处未作该新实际导数，未建议把旧三控制补偿直接冻结后使用。

同一 free-background 诊断里，增加 $v_u$ 或 first-turn $K$ 都降低背景高度；但已有旧 q095 **core-held** 暖响应中，两者的对应高度中心差分却为正。这个实际对比说明低 core 的补偿可能反转方向，不能把本笔记的背景导数冒充真 BVP 的高度导数。
