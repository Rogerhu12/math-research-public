# 完整尾状态的 Hermite 初猜：构造、回放和生产入口核验

日期：2026-11-13。本文只记录一个**输入层数值初猜**及其真实回放。
它没有产生新的接受 BVP，没有运行采用该初猜的新 Newton，
也没有给出无限尾、闭面 held 或 reach 证书。
当前 q122 原作业继续使用其原来的线性初猜，未被修改。

## 1. 可复用的数据是什么

同一个物理尾问题在 q098 和 q106 两个已接受前缀的完整切口高度
\(H_0,H_1\in\mathbb R^{28}\) 上，已经分别保存了真正收敛的尾状态及
完整的逐 stage 变分流。两个 snapshot 的 `identityCanonical` 逐字相同；
这包括全部物理和数值参数、576 个 stage、raw 节点、far graph、半径以及冻结源身份。

每个状态有 577 个节点，每节点保存 \((Q,\pi)\in\mathbb R^{56}\)。
全部状态共 32,312 个 Float64；576 个 \(56\times56\) 流矩阵共
1,806,336 个 Float64。原存储器保留所有数值，并已作原值逐 bit 回环核验。
这与只保存切口 `heightJetJacobian` 是不同的数据：单独的切口矩阵不能重建每个内部节点的响应。

q098 的原接受包早于全流持久化，因此另用**同一完整 H、同一接受状态**上的真实 full-audit bootstrap packet
绑定其流 snapshot。生成器把这个额外 packet 单独列为输入，不改原接受包。
q106 使用其原 final tail packet 及 call0003 snapshot。

所有原始输入、sidecar、源文件的路径和完整 SHA256 都在
[回放报告](2026-11-13-strong-q122-collinear-hermite-input-replay-r3-report.json)
中逐项列出。原预测器为冻结的
`78718-tail-tangent-predictor.mjs`，SHA256
`8d39830939a52fc40f7de06cf5a2a9de9959f94058594051a7989b8b40744459`。

## 2. 初猜公式

把全部 shooting states 连接为向量 \(z_0,z_1\)，记
\(u=H_1-H_0\)、\(d=z_1-z_0\)。从两个已保存的完整流矩阵，按原 graph/transport
反扫和前扫公式，计算沿同一 \(u\) 的全态切向响应 \(v_0,v_1\)。
这里的切向响应是原有限离散问题的数值量，不是已经获得区间认证的无限维导数。

对于目标 \(H_*=H_1+\alpha u\)，使用在两端状态和两端切向量上插值的三次 Hermite 多项式：

\[
 z_{\rm cub}=z_1+\alpha v_1+\alpha^2 a_2+\alpha^3 a_3,
 \qquad
 a_2=(v_0-d)+2(v_1-d),\quad
 a_3=(v_0-d)+(v_1-d).
\]

代码用已经计算的当前线性预测作基底，再加这两个 correction。
例如 \(\alpha=2\) 时，等价展开是
\(28z_0+12v_0-27z_1+18v_1\)，但实现不采用这种更容易发生消差的展开。
切口 Dirichlet 分量最后显式设为完整目标 \(H_*/r_{\rm cut}^4\)。

若 \(H_*-H_1=\alpha u+w\)，可以写出启发式
\[
 z_{\rm lin}(H_*)+\alpha^2a_2+\alpha^3a_3,
\]
其中正交分量 \(w\) 仍只使用当前点的原线性预测。
这没有包含沿 \(u,w\) 的混合高阶项，因此**本文共线回放不能验证新 frontload 方向的表现**。
生产默认仅接受近乎共线的输入；投影启发式必须显式选择并重新进行原真实求解。

## 3. 输入约束与接受边界

新生成器为
[strong_full_flow_hermite_warm_v3.py](../computations/strong_full_flow_hermite_warm_v3.py)，SHA256
`f60cba658e06d364b4dd5b894bd3ec97ab8877cf7b76fe4be771b2f8e62138da`。
它不启动 Node、不积分 ODE、不计算新尾残差、不作 Newton。

- 两个原 primary 必须真正完成接受，原 raw 全 H 必须与真实已审计尾相同；额外 bootstrap 必须绑定同一接受状态。
- 完整 tail identity、源 map、全部状态/H、全部流 sidecar 哈希、布局和覆盖都必须匹配。
- 目标完整 H 来自已经完成的原 warm geometry screen，且该 screen 的接受基线/原 raw 身份必须匹配。
- 默认 \(\alpha\in[-1,2]\)，只给比较运算留 \(2\times10^{-12}\) 的舍入余量；普通 H 范数和按频率平方加权的正交相对量都不得超过 \(10^{-8}\)。这些是初猜适用性检查，不是收敛半径证明。
- 不适用时写报告而不写 warm。数学候选仍可使用原线性初猜，不因这个输入优化器拒绝而被判为不存在。
- 输出明确含 `new_target_accepted=false`，没有伪造 `response`、新 audit 或新 `fullFlowTangentSnapshot`。
- 原生产入口仍要求完整目标 H；原非线性残差、全 J、正性、线搜索、真实边界、RMS 和最终物理审计全部保留。

原冻结 worker 的额外 factory 等价 probe 只在 `call===1` 执行。
q106 final call0003 的该附加字段为 null；v3 按这个原规则如实记录。
每次都必须存在的完整 base/flow bit 回环没有放宽。
早期 r1 的整数索引装配错误和 r2 对这个附加字段的过度限制都在归档中保留；
两次均在生成新 warm 或启动 worker 前退出，不是数值求解失败。

## 4. 实际回放结果

真实目标取自 q106 到 q122 的原 pure-secant scale2 完整 warm screen。
用所有 28 个 H 分量计算得
\(\alpha=2.000000000000006\)，普通正交相对量为
\(7.34086456437689\times10^{-18}\)，频率平方加权相对量为
\(2.9362887983669734\times10^{-17}\)。

生成器只读取 q098/q106 两个接受点及目标 H，不读取 q122 尾解。
随后独立比较才读取原 q122 作业真正算完的第一次新 H 尾响应：
残差 `1.499946469287228e-9`，原容差 `2e-9`，完整 H-J 为 2408 项。
这个参考响应的 `request.audit=false`；它是收敛的有限尾参考，
不能代替 q122 整 BVP 接受或最终物理审计。

比较完整的 \(577\times56\) 数组，结果如下。
“节点相对差”以该参考节点所有分量的最大绝对值为分母，最小分母截在 \(10^{-250}\)。

| 与同一真实收敛尾参考的差 | 原线性初猜 | 新三次初猜 | 原差 / 新差 |

| 全部状态最大绝对差 | 0.26858179730107423 | 0.00003140269226460657 | 8552.8271 |
| 最大节点相对差 | 0.011113660605774973 | 0.0000058601738679048755 | 1896.4728 |

完整目标 H 和切口 Q 的 bit 比较都通过。
这些是与同一个数值参考的全量差值，**不是对未知精确尾的严格误差上界，也不是 Newton 次数收益**。
