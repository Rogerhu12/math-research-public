## 4. Exact numerical cache contract

The scope is one original build_inequality_rows call. The complete small key retains the original grid/arbitrary tag, stage, angle, branch, actual cell/u/phi binary64 words and all six three-component cotangent arrays. Signed zeros are not collapsed. Only a key with a future repeated selected request is worth storing.

A usable complete key additionally binds the immutable full-point bytes owner, caller and prepared point words, current model/base/seed canonical objects, actual code objects and whole source files, fixed carriers and Q, complete query, actual mean/radial/calibration values, consumed fixed integration reference file bytes, full selected roots and all stored stage matrices/orders/provenance. A missing J9 or unavailable reference/cache record causes an original-call miss; key construction does not compute it.

The optional probe checks the plain environment without wrapping the original numerical point_vjp in a new no_grad context. Original point_vjp deliberately constructs its own internal reverse graph and returns the full NumPy gradient. External transforms, inference/unknown modes or source/key incompatibility bypass reuse. No active graph or derivative tape is stored.

After an original call really returns, the complete numerical result may be stored in a bytes-owned read-only payload. A hit returns a new complete native float64 copy. The original transpose and row arithmetic execute again for that row. The cache has a 64MiB retained-gradient-payload bound and LRU eviction; full M160/J923 free size 1,333,370 gives 10,666,960 bytes per gradient and at most six such retained gradients. These are retained-payload bounds, not claims that all temporary arrays or key metadata fit in 64MiB.

The unchanged normal/helper entry and exit checks, all control/data guards, original stage/final rereads and original point_vjp exceptions are retained. The new selector itself checks its complete scope at construction and whenever it constructs a complete key; its close operation releases entries and does not claim a new full-scope exit reread. An optional key/allocation/clone/source failure falls back to the original operation; an exception from the original scientific pullback propagates normally. Finally closes the scope and releases stored entries.

Logical requests, actual original attempts/returns, numerical hits, stored/evicted/released entries, payload peak and optional failures are separate reported counters. A cache hit never increments or imitates an original normal point_vjp invocation. Every reported hit binds a previous actual original-return row, matching complete-key and gradient-word digests.

## 5. What equivalence does and does not establish

For identical complete inputs, a numerical hit supplies the full prior result of the same original producer. Every operation downstream of dk retains its original order and arithmetic. The cache stores no derivative function and is not differentiated through. The actual complete scientific source/point/input guards determine whether this condition is met; otherwise the original producer is executed.

If N is the number of original selected rows and H is the number of actual valid hits, the number of actual original curvature pullbacks for that scope is N minus H, with every original row still present. The gain can be zero. Extra source/key hashing, point comparisons and full-gradient copies cost time, so this source derivation proves no wall-time improvement and no whole-job completion guarantee. It particularly does not identify the trial-geometry bottleneck.

The potential per-frame order-two upgrade optimization and lazy rotation-coefficient computation are separate source questions. They are **not included in this entry**. Likewise this entry does not change restoration damping, introduce adaptive policy, reorder geometry before statistics, change profile width or integrate the independent R725 endpoint cutoff.
