# RET96: historical source-receipt and returned-observation JSON layout

Author: construction (GPT-6 Astra Pro; AI-assisted), 2026-11-28.

This package applies complete lexical whitespace formatting to 35 historical JSON files. The exact original snapshot is `1584d5762c3ed81725a2d3cfb5e1d3f6e233af56` in `Rogerhu12/math-research-public`. Two complete mapping files divide the scope by repository directory: 22 note files and 13 computation metadata files. Each mapping contains every original and resulting full path, byte count, SHA-256 and Git blob SHA. No scientific file is deleted and no JSON member or token is omitted.

## Selected records and preserved meaning

The note group consists of old source-preparation receipts, source-only view/provenance descriptions, dispatch and provider-identity receipts, finite source probes, executed manifests and archive descriptions. Their full source strings, literal patches and identities remain unchanged. In particular, a source-preparation record still distinguishes prepared source from actually executed response work, and actual94's source crosswalk still describes its original dispatch rather than any current run.

The computation group consists of seven old R483/R498/R503/R504/R519/R531/R553 source-view plans, four already-returned summary archives, the original run13/run14 official-terminal observation, and run17's first observed accepted-restoration record. The whole plan content, complete parameter occurrences, literal source transforms, declared budgets and future/unpaid fields are retained. The selected source-view JSONs describe historical generated views; their actual scientific source files are not edited. These records do not become a new request or current executable input.

The run13/run14 record retains both official cancellation and the absence of an actual final field. Its separate run17 observation remains separate. Run17's first acceptance remains one actual old observation, not a new final state or a conclusion about a later point. Every returned-summary entry preserves its own original stage, source queue, step order, actual return and cleanup scope. No historical token is refreshed to an invented current value.

Five other completely read small candidates were already compact and are not mutated. Request files, ready objects, queues, workflows, current source/input bindings, original unique inputs, ports and parent91 are outside this package. The separately investigated `current-C` request route was rejected because the original workflows directly listen for pushes to those request paths; this package does not change them or their workflow triggers.

## Exact operation and complete recovery

Only ASCII space, tab, CR and LF outside JSON strings are removed; one final LF is appended. Strings and escapes are tracked exactly. Numbers are never parsed and reserialized to produce a replacement. Full member order, array order, numeric spellings, exponents, negative zero, complete code strings, original paths, errors, failed attempts and unknowns are therefore preserved byte for byte as tokens.

The already published full 3705-byte note formatter and 3718-byte computation-metadata formatter are reused without modification. They consume the respective complete map, an entire separate original checkout, and a separate output directory. Each checks the recorded original whole body and complete resulting whole body. No scientific modules, AST pass, fixture, benchmark or numerical replay are run or added as an admission condition.

A formatted file has a new whole SHA-256 and Git blob. Historical embedded hashes keep their original semantics. An old reader requiring exact original bytes must recover the full original path from the fixed commit above, or use its original Git blob, and verify that identity. It must not accept a newly formatted body under an old hash. All original source/parameter documents remain recoverable as complete files, with no scientific data split, compressed transfer or encoding introduced here.

The two map files are distinct complete logical groups, not fragments of numerical data. Together they list all 35 changed files. Only their `complete_file_map` original rows are fresh publication guards. Their optional formatting commands remain an I/O reproduction aid; no new scientific gate is implied.

## Accounting and publication

The note group removes 48,153 bytes of whitespace; the computation group removes 55,932 bytes. Gross reduction is 104,085 bytes. The small package delivery record gives the exact map/note/delivery overhead and resulting net reduction. Existing formatter runtimes are not copied into the tree again.

All replacements and mapping documents are protected as complete unreferenced Git blobs. Root alone may perform ordinary ref publication after matching the original path, blob and size. Construction writes no refs, queue, request or workflow.
