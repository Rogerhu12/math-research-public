# Complete R723-compatible same-field phase-mesh sources and run21 parameters

## 1. Purpose and exact status

This package closes one concrete source-interface gap. The published producer-bound mesh input accepted the complete legacy 002eb closed-phase report, while the independent R723 producer has a different exact source, schema and five-role evidence definition. Passing an R723 report to the old input would correctly fail its legacy source guard. This package supplies a separate complete input, mesh entry and reader. The complete old source files remain unchanged.

There are three explicitly distinct selections:

| Selection | Complete numerical mesh work | Optional accurate evidence |
| --- | --- | --- |
| No closed-report argument | The entire original work remains available. | The original absent-evidence result is retained. No accurate certificate is inferred. |
| Exact legacy 002eb report | The entire original work remains available. | The entire original legacy binding function is retained, under an internal legacy name. |
| Exact independent 1782 R723 report | The entire original work remains available. | The full R723 validator re-consumes the original complete evidence and a new binder relates it to this exact selected mesh point. |

These are source branches within one mesh program, not three new solver runs. No numerical field, root, geometry certificate, checkpoint, mesh or acceptance result was generated while constructing this package. The source work used complete text and JSON in V8. No local AST, compilation, scientific fixture or numerical test was run. The source reproducers are deliverables for exact reconstruction; they do not add a solver, proof or workflow admission step.

The run21 plans refer to the same existing producer-bound scientific family and its five-eighths seed parameters. They do not turn its prepared inputs or mutable progress into a mesh point. All future point, snapshot, final-checkpoint, complete-report and fee identities remain null. The already prepared original 32/6 no-evidence plans remain complete immutable parents.

## 5. Complete R723 re-consumption before attaching claims

The new binder reads the final main report first. It requires:

- complete is true.
- status is complete-same-field-consumption.
- all_bound_input_and_generated_evidence_bytes_rechecked is true.
- Exact R723 main schema and source.
- Complete declared input and generated-evidence inventories, with no duplicate original path.

It then loads the exact whole R723 producer and calls its full validate_complete_report API with the actual whole main-report SHA. This is the complete validator, not a sidecar-only or flag-only replacement. That validator re-reads the original geometry, original normal32 journals and full physical domain, all ordered leaf ranges, the actual current core, exact ports, both directional passes, all-phase activity and cap bounds, original proof/source records, marked and independent unmarked calculations, complete range evidence and the final sidecar. It re-computes the exact R723 package and compares the entire original dictionaries.

The mesh binder checks the validator's exact return identities and all full-reconsumption flags. It requires the validator's new F/J/root/integrand-call count to be the integer zero. This attached evidence performs rational evidence arithmetic and reads actual NPZ words, but it does not evaluate a new field or root.

The report's source map and proof map must equal the maps returned by the full validator. Every original record must be listed in the final main inventory. All 137 original scientific source records are related to the mesh's actual complete source copies by whole SHA and byte count. Every additional original evidence source and theorem remains bound as well. No basename substitution is accepted without a full byte-identity relation.

The exact complete theorem remains results/R723-directional-normal-flow-support-reach.md, whole SHA256 0edbd1039706186d07412a53c8e5c10411c5966dc36e38a7a504cf923d43e7eb. All original port, phase, normal, holding and R716 proof sources remain required; R723 does not replace them.

The actual original normal report is independently read and must be complete, with all planned original stages and six-jet streams complete and final full byte recheck true. Its actual-input identity and both binding/request canonical identities are recomputed from complete dictionaries.

The original scientific report consumed by normal fees can be a different immutable report version from the mesh capture. A later final report may contain the same exact snapshot and field while adding solver bookkeeping. Such versions are accepted only when the complete point/model/target/provenance/snapshot relationships above are equal. Both actual report records remain separately present. The source does not replace the original normal report hash with a later mesh-capture hash.

A final13 point and a snapshot at the same numerical point are not automatically the same snapshot identity. If the selected final point lacks a complete same-point snapshot, optional accurate evidence cannot be attached. Packet mode may select a real complete trial/cache snapshot; it does not become accepted or final. If a default selected snapshot differs from the certificate's snapshot, select the actual matching snapshot explicitly after it has returned. No future SHA is built into these plans.

## 7. Main/sidecar and late-failure rules

The sidecar must be the exact record declared in generated_evidence_records and the exact record returned by the full validator. Its complete object must equal the validator's independently recomputed sidecar. It must use the exact R723 sidecar schema/source and name this actual absolute final main-report path.

The intermediate-sidecar flag remains explicit: a sidecar written before a later failure is not accepted without the final complete main report and final byte recheck. Both its geometry and original normal report relations remain exact. Full input/output byte checks are repeated at the end of the mesh binding and reader.

The independent unmarked tube is reported separately. It is paid only when the validated unmarked all-phase embedding/outwardness, strict mark-height bound and full twelve-moment additivity interpretation are actually true. Marked reach is not substituted for that independent tube. R718 retains its actual marked support sigma; the new directional reach radius is not substituted for sigma.

A final complete R723 consumption can truthfully contain unpaid geometric conditions. That is still a valid complete evidence input: the new binder preserves null/false, and numerical meshing can proceed. It does not add an all-conditions-passed precondition. In contrast, an incomplete or stale main report is not a complete evidence input.

## 12. Actual scheduling and remaining responsibility

No workflow queue is changed here. The prepared new plans become applicable only after the actual scientific report/point/snapshot and the same-point complete R723 report are available. The complete source-interface note specifies the proper source-dependent order: retain a stable captured field; finish the full normal domain in its original request identity; construct geometry from that complete normal report; complete R723 evidence from that geometry; then run a selected fresh mesh mode and its complete reader.

The original no-evidence mesh plans can still run on a valid actual point without an accurate closed certificate. The old 002eb route can still attach that exact old proof. Neither route is deleted or redirected. A selected new R723 plan requires the supplied R723 report to be a genuine final complete same-point report; it does not require all geometric targets to have passed.

No optimization is restarted. No finite sample is upgraded to a full continuous certificate. The exact full-field source, snapshot, target and complete evidence scope remain visible in every result.

The package is an implementation and complete parameter delivery. Actual run21 fields, full normal and geometry returns, all-phase reach, Gram, grip, holding, centred moment gap and refined mesh convergence are not claimed here.
