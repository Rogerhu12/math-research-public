# R473 — 完整有限轨迹线性乘积中跳过零系数项的条件证明

作者：AI（amplitude）；日期：2026-11-16。

可信度：**已证明（限本文所列 binary64 算术、实际输入和来源条件）；尚未实现、未运行、没有性能或完整接受结论。** 本文不修改 R471、request208、request210 或任一冻结 flow。

## 473.1 结论

对原完整 `linear(A,T)`，若实际被使用的全部 $A$ 和 $T$ 数值词有限，则只跳过 `z===0` 的 $j$ 项，并保留每个非零项的原乘法、加法、括号和 $j$ 顺序，具有以下局部性质：

1. 所有最终有限输出与原循环具有相同 binary64 词，包括零的符号。
2. 若非零乘积或前缀累加溢出，原循环和候选循环的正无穷、负无穷、NaN 分类相同；首次产生非有限累计值的原 $j$ 也相同。
3. 不声明 NaN 的 payload、编码或整个含 NaN raw 数组的字节相同。原 `linear` 自身没有非有限检查；只能在原下游使用同一有限性/分类谓词、且无资源或其它先行中断的条件下，转述相同输出 bad mask，不能虚构一次已执行的验收。

这不要求入射 $T$ 分块，也不要求 $A$ 满足 R470 的零形状前提。对任意实际有限矩阵，跳过的是实际为正零或负零的系数词，而不是“小于阈值”或理论上应为零的数。若不能保证实际被用的 $T$ 有限，直接跳过不安全：`0*Infinity` 或 `0*NaN` 在原循环为 NaN，删除会压掉原非有限结果。因此未来最窄实现须在不合条件时执行原完整循环，而不是拒收状态或增加科学通过门。

本结果仅给可实施的条件命题，不提供新 helper、源码视图或 request。R471 的角通量选择与本结果是两个独立切点；任何未来组合均须另有实际源码身份。

两者的 `linear` 数学正文相同：

```javascript
function linear(A,T){
 const dt=new Float64Array(size*Kdim);
 // The two mean rows are retained; only the original K shape columns
 // enter this multiplication, so mean tangents never feed shape.
 for(let i=0;i<size;i++)for(let j=0;j<Kdim;j++){
  const z=A[i*Kdim+j];for(let k=0;k<Kdim;k++)dt[i*Kdim+k]+=z*T[j*Kdim+k];
 }
 return dt;
}
```

这里 $K=Kdim=2M$，$size=K+2$。$A$ 有 $(K+2)K$ 项；$T$ 是完整 tangent，但这一个乘法只读其前 $K$ 行、全部 $K$ 列，即 $K^2$ 项。最后两个 mean tangent 行没有作为输入喂回形状；两个 mean 的输出行仍完整形成。$M=112$ 时仍输出完整 $226\times224$ 数组。

本次完整源读还核到原 `oneOriginalStep` 的顺序：先真实完成原 no-J 四次 field 和 nextState；再从四个已捕获现场形成 Aa/Ab/Ac/Ad；然后按原次序运行 ta/tb/tc/td 的 `linear` 与原 RK tangent 组合。`linear` 没有 `Number.isFinite`、`finiteArray` 或主动 throw。`fromCaptured` 的局部 Jacobian 会经过其 variation 的原检查，但后续 RK 形成的入射 tangent 不因此自动获得全程有限保证。

所以不能从“原局部 Jacobian 已 finite”就省略对本次被用 $T$ 的责任，也不能把原 mean tangent 的非有限词误写成此乘法实际读取的输入。

## 473.3 算术和访问条件

本命题使用以下明确条件。

1. 数组、索引和维度是上述原正常调用的实际对象；数组长度相容，在同一调用中没有外部并发修改。没有 getter、Proxy、用户回调或其它从“读取某个元素的次数”取得副作用的对象。
2. 实际所有被用的 $A_{ij}$ 与 $T_{jk}$ 是有限 binary64 数值，允许正负零、正常数和次正常数。只要求本乘法实际读到的前 $K$ 个 T 行，不扩大到未读 mean 行。
3. 每个乘法先按 binary64 round-to-nearest, ties-to-even 形成数值词，再做原加法；不把乘加融合为一次 FMA，不重关联，不改变非零项的 $j$ 次序，不用 pairwise/reduction 重排。
4. 结果仍由 `new Float64Array(size*Kdim)` 创建，所有累计器初始为正零。必须保留全部输出槽；不能把某些 row/column 删除。
5. 两条被比较的局部计算均完成；不同成本引起的资源停止、外层信号、分配失败等不在“同一次正常完成”的结论中被抹去。

候选操作只是给原 $j$ 项添加 `if(z===0) continue`。该判断同时识别正零和负零；不采用容差，不跳过非零的次正常系数。非零项仍按原 `dt[i*Kdim+k]+=z*T[j*Kdim+k]` 执行。

## 473.4 一个累计器不产生负零

固定输出 $(i,k)$。原循环可写成

$$
s_0=+0,\qquad
p_j=\operatorname{RN}_{64}(A_{ij}T_{jk}),\qquad
s_{j+1}=\operatorname{RN}_{64}(s_j+p_j),
\quad j=0,\ldots,K-1.
\tag{473.1}
$$

必须把 $p_j$ 看作已经完成一次乘法舍入的 binary64 词。有限输入的乘积可能溢出成无穷，或下溢成有符号零；后者不是删除该非零系数项的理由，原操作仍要执行。

**引理 473.1。** 在 (473.1) 的累计尚保持有限时，$s_j$ 不会成为负零。

**证明。** binary64 的每个有限值都是最小正次正常量

$$
\delta=2^{-1074}
\tag{473.2}
$$

的整数倍。因此两个已经形成的有限 binary64 数相加，其准确和若非零，绝对值至少为 $\delta$，不可能落入会舍入为零的开区间。这里即使某个乘法的准确实结果小于 $\delta$，它也已经先舍入成 $p_j$；不能把未舍入乘积偷偷带入加法。

若有限的准确和恰为零：两个非零相反数准确抵消时 RN 结果为正零；正零与任意有符号零相加也为正零。只有负零加负零给负零，但归纳假设排除了累计器左操作数为负零。初始 $s_0=+0$，故每个仍有限的 $s_j$ 都不是负零。证毕。

特别地，保留的非零系数项可能产生 $p_j=-0$。若此前累计为正零，原结果仍是 `+0 + -0 = +0`；若此前是有限非零值，加任一种零都保持原词。不能因乘积可能为负零而错误地认为所有零项都不能删，也不能因此把原乘法直接改成理论非零值。

这条论证依赖原“先乘、后加”的实际表达式。若另引入 FMA，未舍入的小负乘积可能直接与正零合并，源问题已改变；本文没有支付这种替换。

## 473.5 删除实际零系数项的有限词结论

**引理 473.2。** 当 $A_{ij}$ 为任一种零且 $T_{jk}$ 有限时，$p_j$ 是某种零；在有限累计器上该 $j$ 项不改变输出词。

**证明。** 有限数乘有符号零为有符号零，不形成 NaN。若累计有限非零，加零精确保持该词；若累计为零，引理 473.1 保证它是正零，而正零加任一种零仍为正零。证毕。

**定理 473.3（有限输出）。** 在第 473.3 节条件下，候选循环删除所有 `A[i*K+j]===0` 的 $j$ 项，保留其它项的原运算和顺序；对任何最终有限输出，它与原循环逐词相同。

**证明。** 按原 $j$ 序作归纳。遇到零系数项，原有限累计词不变，候选不写；遇到非零项，两者以相同输入词执行同一个已舍入乘积和同一个加法。故每个有限前缀均相同。非有限一旦出现不会再恢复为有限，这一点由下一节证明；因此最终有限槽的全部前缀都属于上述归纳，结论成立。证毕。

删除项以“整个 $j$ 的所有 $k$”为单位不改变结论，因为各 $(i,k)$ 的累计互相独立，原 $k$ 循环没有交叉写入，也不改变 $A$ 或 $T$。所有非零 $j$ 的原先后次序仍保留。

本定理不要求 $T$ 稀疏或分块。即使先前一般场把完整 tangent 混成稠密矩阵，只要本次实际被用词有限，任何实际零 $A_{ij}$ 的乘积行仍可按这个局部定理删除。也不要求先知道它为何为零；R470/R471 可以解释某些零现场，但不是本定理的额外门。

## 473.6 非零乘积溢出、NaN 与失败语义

有限的两个乘数不能直接相乘得到 NaN，但可以得到正或负无穷。有限前缀相加也可能溢出；相反符号无穷相加可产生 NaN。必须分别处理这些情况，不能把“输入有限”误写成“所有乘积和前缀必有限”。

**引理 473.4。** 若某前缀已是正无穷、负无穷或 NaN，添加有符号零保持同一分类；以后只执行原乘加时，该槽不能恢复成有限数。

**证明。** 正负无穷加任一种零仍为原符号无穷，NaN 加零仍为 NaN。无穷加有限数或同符号无穷仍为该无穷，加相反无穷变 NaN；NaN 再加任何数仍为 NaN。这些规则不产生有限数。证毕。

**定理 473.5（非有限分类）。** 在第 473.3 节条件下，两条循环第一次产生非有限累计的原 $j$ 相同，其后每个保留位置及最终输出的分类在有限、正无穷、负无穷、NaN 四类间相同；有限词仍如定理 473.3 相同。

**证明。** 被删零项不能首次产生非有限值。首次非有限必须来自原保留的非零项；在它之前有限累计词相同，故该项的同一运算在两者给出同一分类。其后由引理 473.4，删去的零项保持分类，保留项仍是相同输入乘积；分类归纳成立。证毕。

本文只证明 NaN 分类相同，**不证明 NaN payload/符号/存储编码相同**。一次被删除的 `NaN + 0` 以及 Float64Array 写回可能涉及实现自己的 NaN 编码选择；不能据分类结论宣布完整 raw 数组 SHA、逐字 observer 或 NaN payload 相同。正负无穷的符号则明确保留。

原两份 flow 的 `linear` 都直接返回 dt，没有主动非有限验收。因此准确的“失败语义”表述只应是：若下游在同一时点对这些输出采用相同的 `Number.isFinite`、NaN/无穷分类或同一 first-bad-index 规则，则它们取得同样 bad mask 和位置。原代码是否会在那个时点真正报错，必须沿实际 caller 另核，不能由本文加一个新 throw 后说是原门。

如果下游观察 NaN 的 raw 编码、依赖时间或先被资源异常打断，本文不声称那部分行为相同。对正常有限链，则可在每次局部调用条件均满足时逐次使用定理，但仍不能免去真实源码接线、资源范围和原最终门。

## 473.7 不合条件的明确反例与最小安全方向

若某个被用 $T_{jk}=+\infty$ 且 $A_{ij}=0$，原乘积为 NaN；若把该 $j$ 项直接删掉，一个原本正零的累计器可能保持正零。把 $T_{jk}$ 改为 NaN 同样失败。这是纯语义反例，没有生成或执行数值 fixture。

因此只看 A 的稀疏/零模式不够。未来最窄候选可先在同一次实际调用中确认所有被用 T 有限，并依原局部 Jacobian 来源确认 A 有限；无法确认就执行原完整循环。也可以在未来独立源中明确扫描二者。这个判断只选择实现，不能把“不合条件”变成新的科学拒绝或接受门。

不需要为了本定理预先算完所有非零乘积、检查每个前缀再运行一遍：第 473.6 节已经支付其分类范围。若以后要求连 NaN raw 编码都相同，应另限只对原完整有限乘法返回作逐词声明，或给更强实际机制；不能把本分类命题悄悄扩大。

输入 mean tangent 的最后两行不在此乘法的读集合内。它们可能影响原后续 RK 的对应 mean 项，但不能为本乘法添加无关的“两个 mean 必须零/有限”前门。所有输出 mean 行仍分配、仍按实际 A 的系数计算；原 primal 两 mean、状态、端口和高度汇合保持原责任。

## 473.9 运算量范围

原完整乘积执行 $(K+2)K^2$ 次乘加。若 $Z$ 是当前 A 中实际非零词数，则这种候选保留 $ZK$ 次乘加，加上读取/选择 A 和确认被用 T 的线性扫描成本。输出仍为完整 $(K+2)K$ 数组；没有减列、减行或缩小求解问题。

在额外满足 R470/R471 零现场且原完整数值 A 确有每模态小块结构的条件下，$Z$ 可能小于稠密项数，因而该切点有实际运算量改进机会。这里没有假定任何已运行阶段的 Z，没有由聚合计数复原 A，没有承诺加速倍数，更没有用此取代完整 kernel 的实际执行。
