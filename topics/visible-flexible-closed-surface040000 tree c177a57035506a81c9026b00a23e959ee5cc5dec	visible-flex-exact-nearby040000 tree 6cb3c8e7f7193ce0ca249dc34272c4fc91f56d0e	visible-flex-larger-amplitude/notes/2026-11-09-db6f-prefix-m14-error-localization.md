# M14 前缀误差非单调：源投影与表示误差的分离

状态：**数值诊断；因果试验因实际内存压力改为串行待重跑。** 2026-11-09，`/root/coupled_prefix`。

M12 和 M14 的 frozen profile、angular chart、尾物理参数相同。完成的 M14 联解通过原非线性边界条件，尾的源度量误差从约 $1.96\times10^{-8}$ 降到 $8.56\times10^{-9}$，但前缀的保存诊断从 $8.95\times10^{-9}$ 回升到 $7.95\times10^{-8}$。不能把尾改善称作整个曲面的频率收敛。

## 在同一保存状态上分离两类导数

`scripts/db6f-prefix-metric-localize.py` 在全部保存节点、中点及均匀补充点上，分别用两种经向系数导数：

- 保存的 C² Hermite 多项式的真实导数；
- 在同一系数值上调用原来角积分分辨率的非线性 Galerkin RHS。

两者均加入同一真实平均高度速度，并按相同角坐标链式法则转到物理 $(s,\theta)$。用 1024 个角点计算归一化 $E,F,G$ 误差的 FFT $\ell^1$。这只是有限采样诊断，不是连续上界。第二项也不是一个新的精确 ODE 解；它是在保存状态处评价源速度场。

| 数值项 | M12 | M14 |
|---|---:|---:|
| 保存表示的最大 metric | $8.95134441\times10^{-9}$ | $7.94615496\times10^{-8}$ |
| 同状态源 RHS 的最大 metric | $8.95134441\times10^{-9}$ | $7.94615496\times10^{-8}$ |
| 源 $E$ 误差最大值 | $1.29504364\times10^{-9}$ | $7.94615496\times10^{-8}$ |
| 源 $F/a$ 误差最大值 | $5.86208178\times10^{-10}$ | $2.08595759\times10^{-8}$ |
| $G/a^2$ 误差最大值 | $8.95134441\times10^{-9}$ | $1.32299183\times10^{-8}$ |
| 源投影速度对 Frenet 速度最大差 | $1.75001373\times10^{-8}$ | $9.52538323\times10^{-7}$ |
| 保存导数与源 RHS 的速度最大差 | $1.00283157\times10^{-10}$ | $1.59966567\times10^{-10}$ |

M12 最坏 metric 是入口附近 $s=0.00196561545$ 的 $G$ 项；M14 最坏是 $s=0.27483516074$ 的 $E$ 项，源投影速度差的最坏点在 $s=0.11814752887$。因此本次回升已经出现在源 Galerkin 状态与速度的组合中，不能用加密导出 Hermite 网格或修改最后的公共 cut 来解释掉。

## 尚待区分的原因

M12 的高阶中央 support 系数约在 $10^{-10}$ 至 $10^{-9}$，M14 最后几个增大到 $1.19\times10^{-8}$。M14 的入口投影二阶误差为 $3.00\times10^{-6}$。它的最高尾模仍近似服从正常的线性 DN 比率；目前没有发现明显的尾斜率符号或数量级错误。

一种具体待验机制是高模边值问题放大径向 collocation 的全局误差。当前原容差 $2\times10^{-9}$ 只控制数值配点残差，不直接控制中央参数误差或全部遗漏的 Fourier 度量系数。反过来，不能在试验前便认定收紧容差必然修复回升：固定阶数的 Galerkin 解本身也可能给非单调的截断误差。

为区分二者，`scripts/db6f-prefix-affine-replay.py` 保持 M14 的同一度量、14 模、512 点角积分和最后真实 `tail_0004` 的 DN 及 Jacobian，仅将前缀 collocation 容差降到 $10^{-11}$，从全部保存自适应节点开始。输出 stem 为 `2026-11-09-db6f-prefix-flat-v17v18-m14-affine-tol1e11`。

**此试验明确保存为 `actual_nonlinear_tail=False`。** 固定仿射 DN 的输出必须再用原真实非线性 DN 校正与审计，才能叫作新的真联解。独立 M16 真实延拓则继续使用完成的 M14 作初猜，两条路线的输出分开保存。

第一轮配点报告残差 $2.00\times10^{-9}$，需要从 2633 点增加到 5890 点。此时实际 cgroup 匿名内存达到 7.60 GB，而上限为 8 GiB、文件缓存仅剩约 94 MB；为保护尚未落盘的 M16 Newton 状态，本代理主动 Ctrl-C 中断了可廉价重跑的 M14 试验，工具确认退出码 1。输入、脚本、第一轮记录和内存证据保留在 `2026-11-09-db6f-prefix-flat-v17v18-m14-affine-tol1e11-interrupted.json`。后续还观察到系统 OOM 计数从 7/1 增加到 9/2，但不能由计数确定被终止的是哪个进程，故不归因到某个数学求解。

当前没有紧容差成功 CP，没有因果判断，也没有分支不存在结论。待 M16 响应落盘或其他大任务释放后，使用相同输入、全新输出 stem 串行重跑。
